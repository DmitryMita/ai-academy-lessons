⚡ <b>Модуль 1: Prompt Caching, контекст и экономика токенов</b>

Контекстные окна моделей выросли до сотен тысяч токенов, но пересылка истории на каждом шаге агента приводит к двум проблемам:
1. <b>Взрывной рост счетов за API</b> и задержки ответа (TTFT).
2. <b>Context Decay и Lost in the Middle</b> — размывание внимания модели в середине длинного контекста.

—

🧠 <b>Что такое Prompt Caching под капотом?</b>
Инференс-провайдеры сохраняют вычисленные матрицы внимания (<i>KV-Cache / Key-Value Cache</i>) в сверхбыстрой памяти графических процессоров (H100/A100).
• <b>Принцип префиксного совпадения (Prefix Match):</b> если цепочка токенов с начала промпта точно совпадает с предыдущим запросом, сервер не тратит вычисления на матричные умножения, а мгновенно подгружает готовый KV-кэш.
• Модель считает только дельту — новые токены в конце запроса!

—

📊 <b>Сравнение провайдеров:</b>
• <b>Anthropic Claude (3.5 Sonnet / Haiku):</b>
  - Управление через брейкпоинты: <code>cache_control: {"type": "ephemeral"}</code> (до 4 точек).
  - Порог: от 1024 токенов (Sonnet) / 2048 (Haiku).
  - Экономика: запись кэша +25%, <b>чтение кэша — скидка 90%!</b>
  - TTL: 5 минут, продлевается при каждом попадании (rolling).

• <b>OpenAI (GPT-4o, o3-mini):</b>
  - Автоматическое кэширование блоками по 128 токенов при промпте от 1024 токенов.
  - <b>Скидка 50%</b> на кэшированные входные токены.

• <b>Google Gemini (1.5 Pro / Flash):</b>
  - Явный объект <code>CachedContent</code> от 32 768 токенов.
  - <b>Скидка 75%</b> на запросы + почасовая оплата хранения в памяти.

—

📐 <b>Золотое правило архитектора:</b>
Никогда не ставьте динамические переменные (текущее время, ID сессии) в начало промпта! Изменение первого же токена уничтожает весь последующий кэш.
<b>Правильная иерархия:</b>
<code>[Системная роль] → [MCP-инструменты] → [База знаний] → [История] → [Свежий ввод]</code>
